# 世界观选品 SOP 工具包

> 一套把"我感觉这个题材能做"变成"可审计决策"的工具,
> 用于 Hybrid-Casual SLG 立项前 3-4 周的候选世界观筛选。

---

## 这是什么

4 步漏斗, 每一步都有对应的模板或脚本:

```
第 1 周  五维打分      → 10-20 个候选 → 入围 5-8 个
第 2 周  三故事线验证   → 入围 5-8 → 通过 3-5 个
第 3 周  机制反推验证   → 通过 3-5 → 闭环 2-3 个
第 4 周  买量可行性    → 闭环 2-3 → 可立项 1-2 个
```

完整方法论见 **[SOP.md](SOP.md)**。

---

## 快速上手(5 分钟跑通第 1 周)

```bash
cd 世界观选品SOP

# 1. 用 benchmark 数据跑一遍, 看看输出是什么样的
python3 scripts/评分器.py data/打分表_benchmark.csv

# 2. 复制空白模板, 填你自己的候选世界观
cp data/打分表_template.csv data/打分表_我的项目.csv
# 用 Excel / Numbers / VS Code 打开填分, 注意保持 UTF-8 with BOM 编码

# 3. 跑评分器
python3 scripts/评分器.py data/打分表_我的项目.csv

# 4. 保存报告
python3 scripts/评分器.py data/打分表_我的项目.csv -o 我的项目_第1周报告.txt

# 5. 调通过线(默认 20, 可自定义)
python3 scripts/评分器.py data/打分表_我的项目.csv --threshold 22
```

评分器会输出:
- 按总分排序的所有候选
- 入围榜(≥ 通过线)
- 边缘候选(通过线 - 2 到通过线)
- 一票否决清单(有维度 ≤ 1 分)
- 每个候选的五维可视化

## 谁用 / 什么时候用

| 角色 | 主导的步骤 | 投入时间 |
|---|---|---|
| 制作人 / 主策 | 第 1 周: 召集打分; 第 2 周: 写故事线 | 第 1-2 周全程 |
| 研发负责人 | 第 3 周: 机制反推 | 第 3 周全程, 第 4 周配合 |
| 发行负责人 | 第 4 周: 买量可行性评估 | 第 4 周全程 |
| BI / 增长 | 第 4 周: CPI / LTV 预估 | 第 4 周 |
| 创意负责人 | 第 4 周: 素材可拍度评估 | 第 4 周 |

**适用场景**:
- 新产品立项前 2-4 周
- 老产品题材复盘 / 新赛道拓展评估
- 多个候选并行时的排序决策

**不适用场景**:
- IP 授权已经定死, 世界观无选择空间(这时候直接进机制设计)
- 玩法原型验证(机制先行的产品, 不是世界观先行)
- 已经上线产品的版本迭代(这是运营工具, 不是选品工具)

## 关键判据速查

### 第 1 周通过线
- 总分 ≥ 20 = 入围
- 总分 18-19 = 边缘(入围 < 5 个时才复活)
- 任一维度 = 1 = 一票否决

### 第 2 周通过判据
- 三故事能一口气写完
- 外人盲测三问都能顺畅回答
- **盲测者必须覆盖目标市场的文化背景**

### 第 3 周通过判据
- 劳作 / 冲突 / 联盟三组机制自检全 √
- 机制地图能画出完整的"资源流"闭环
- 没有"虽然世界观里没有, 但我们可以这样设计"

### 第 4 周通过判据
- 四维总分 ≥ 14
- 素材可拍度 ≥ 4(最硬约束)
- 每个子维度不低于 3

## 常见问题

**Q: CSV 为什么要用 UTF-8 with BOM?**
A: Windows Excel 打开无 BOM 的 UTF-8 CSV 会乱码, 加 BOM 可以让
Excel / Numbers / VS Code 都正确识别中文。Python 脚本用
`utf-8-sig` 读取, 会自动跳过 BOM。

**Q: 评分器需要装什么依赖?**
A: 零依赖, 只用 Python 3.8+ 标准库。Mac / Linux / Windows 都能跑。

**Q: 团队只有 2-3 人, 打分结果靠谱吗?**
A: 参见 SOP.md 的 FAQ Q1。建议找团队外 2-3 人参与打分, 打分分歧
本身就是项目风险点的暴露。

**Q: 跑完 4 周只剩 0 个候选怎么办?**
A: 这往往是好结果, 说明方法论严格。回到第 1 周扩充候选池, 特别是
考虑 "已有头部题材 + 差异化变量"(比如"末日 + 克苏鲁")。

**Q: 这套 SOP 能用于非 SLG 吗?**
A: 核心框架可用, 五维定义要调整。比如 ARPG 的"集体性"权重应当降低,
"美术差异化"权重应当提高。SOP 第 8 节附录 B FAQ Q6 有说明。

## 修改 / 迭代本工具包

- `SOP.md` 里的"通过线"是经验值, 可以根据你们团队的历史立项成功率调整
- `data/打分表_benchmark.csv` 里的 15 个题材是 2025-2026 年数据,
  建议每 6 个月更新一次(参考最新榜单和 CPI 数据)
- `scripts/评分器.py` 可以增加按权重计算总分、输出 Excel 报告、
  雷达图可视化等功能, 但保持零依赖原则
