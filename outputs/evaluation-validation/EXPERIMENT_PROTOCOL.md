# SLG Evaluation Validation Protocol

> Date: 2026-05-07
> Purpose: test whether the current SLG project evaluation system can score known market products without hindsight bias.

## Product Set

The validation set contains five market products or product families:

| Candidate | Product |
|---|---|
| Candidate A | Whiteout Survival / 寒霜启示录 |
| Candidate B | 疯狂水世界 |
| Candidate C | Last Asylum: Plague / 乌鸦医生 |
| Candidate D | Top War + Top Heroes |
| Candidate E | Kingshot |

## Separation Rule

This validation has two separated stages.

Stage 1 creates simplified reverse pitch materials from public sources. It must not score, rank, or use present-day market success as proof of project quality.

Stage 2 scores only the Stage 1 PDFs and the locked rubric below. It must not browse for extra success data, revenue data, or current rank data during scoring.

## Stage 1 Output

Each Candidate PDF must use the same structure:

1. One-sentence project hypothesis
2. Theme and player identity
3. D0-D1 front-end entry
4. D2-D7 progression and retention
5. D7-D30 SLG / alliance / map backend
6. Monetization anchors
7. UA creative angles
8. Key risks and unknowns
9. Source appendix

When only current-version information is available, the material must mark it as "current sources used as backward inference; early version pending verification".

## Stage 2 Rubric

Use the current website 7-dimension, 100-point SLG project scoring table:

| Dimension | Weight |
|---|---:|
| User trend fit | 15 |
| First-screen hook and D0 loop | 15 |
| Lightweight granularity fit | 10 |
| SLG backend carrying capacity | 15 |
| Monetization anchors | 15 |
| UA and creative boundary | 15 |
| Verifiability and executability | 15 |

Decision bands:

| Score | Decision |
|---:|---|
| 80-100 | Can enter project validation |
| 65-79 | Small-sample validation |
| 50-64 | Observe / gather more proof |
| <50 or hard-gate hit | Do not greenlight |

Hard gates:

- No external evidence
- Front-end entry and backend are disconnected
- Theme cannot explain war pressure
- Monetization is only generic power selling
- Key data is unavailable and treated as fact

## Scoring Neutrality Rules

- Do not increase score because a product is now famous.
- Do not use current revenue, download rank, publisher reputation, or known hit status as scoring evidence.
- Score what the Stage 1 material would have supported at a pitch review.
- If a dimension has insufficient evidence, score conservatively and state the missing proof.
- Keep product success and evaluation quality separate: a product can be commercially successful while the pitch-material score remains medium.
